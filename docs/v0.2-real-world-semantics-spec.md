# v0.2 Real-World Form Semantics Specification

## Objective

Make contracts from existing Formly 6.1 applications useful for E2E planning
when forms contain keyless layout groups, display-only templates, and dynamic
expressions. Preserve the safe declared-config extractor and add an explicit,
trusted scenario compiler for synthetic model and form-state inputs.

## Contract changes

The schema version becomes `0.2.0` and adds:

- `display` as a node kind for `template`-only fields;
- `dynamicRules` for function or Observable-like expression sources;
- `optionSource` so static-empty, dynamic, and asynchronous choices are
  distinguishable; and
- `state` for the current hidden, readonly, and disabled values when known.

String and boolean expressions remain in `conditions`. A dynamic rule records
the target property and source category without serializing function source.
Resolved contracts may additionally record the JSON-safe value produced for
that target.

## Identity

A keyless node never claims the inherited model path as its own semantic
identity. Its ID is structural and includes its full tree position, even when
it is nested under a keyed group. Keyed controls continue to derive IDs from
model paths. Only genuine keyed collisions produce duplicate-identity
diagnostics.

## Declared extraction

`extractFormContract` remains pure and non-mutating:

- it never invokes functions or subscribes to asynchronous values;
- recognized expression callbacks become `dynamicRules`, not opacity
  diagnostics;
- callbacks outside the expression surface, including validators, parsers,
  hooks, and function array templates, remain diagnostics; and
- template-only nodes become display nodes rather than controls.

## Trusted scenario compilation

`compileFormContractScenario` is a build/CI API. The caller supplies:

- a `FormlyFormBuilder` configured with the application's real Formly
  providers;
- a factory returning a fresh field tree;
- a disposable synthetic model; and
- optional synthetic form state.

The compiler invokes Formly once, then projects the built tree through the same
allowlist as declared extraction. It records resolved required, readonly,
disabled, hidden, and option values while retaining their declared dynamic
source metadata. Resolved option rules reuse the public option projector, so
application-only properties on option records never enter `resolvedValue`.
Other resolved values are retained only for targets represented by the
contract: state booleans, presentation/type text, options, and allowlisted
locator attributes. An expression target outside that set remains declared
and receives an `UNSUPPORTED_RULE` diagnostic.

The synthetic model and form state are structured-cloned before the build.
Nested builder mutations therefore cannot affect caller-owned objects, and a
non-cloneable input fails with a stable `TypeError` before application code is
run.

The compiler is not exposed from an MCP request handler. It does not wait for
remote data or claim browser parity. Observable-like option sources remain
asynchronous unless their values are already materialized by the controlled
build.

## Acceptance criteria

- Two sibling or nested keyless layout groups receive deterministic structural
  IDs with no false duplicate diagnostic.
- Function expressions for visibility, required, readonly, disabled, and
  options are represented without being called by declared extraction.
- A trusted synthetic scenario resolves those same initial values through the
  real Formly builder.
- Template-only fields are `display` nodes and preserve JSON-safe template
  content.
- Choice nodes distinguish static empty options from dynamic and asynchronous
  option sources.
- Unsupported negative, fractional, or unsafe numeric key segments use
  deterministic structural identity and receive an `UNKNOWN_FIELD_SHAPE`
  diagnostic rather than producing an invalid contract.
- Formly `RegExp` patterns receive an `UNSUPPORTED_RULE` diagnostic until a
  versioned contract representation is defined; string patterns remain
  supported.
- Runtime validation, canonical hashing, focused regressions, the synthetic
  Formly integration test, and all repository checks pass.

## Out of scope

- Executing callbacks in MCP or other query paths.
- Waiting for remote option providers or lifecycle-driven UI behavior.
- Parsing JavaScript function source into a rule AST.
- Browser parity, selectors, Playwright generation, or production MCP delivery.

## Executive conclusion

**LIN-0 remains inconclusive.** The bounded harness can load exact TypeScript
program configs, exercise project-reference source redirects and declaration
outputs, resolve direct calls across the requested import conventions, classify
overlap deterministically, scan lazy-loader topology without retaining routes,
audit a module-only report, scan application bundles for locally supplied
forbidden literals, and evaluate explicit resource budgets. Focused tests prove
those harness behaviors with temporary synthetic inputs.

The retained public Angular rehearsal is not representative workplace evidence.
It reproduced four exact direct factory calls with zero TypeScript diagnostics,
but it has one workspace-wide config, no project reference, no declaration
consumer/source-redirect pair, no lazy route, no overlapping program case, no
application-bundle isolation input, and no approved workplace performance
budgets or samples. Its exact retained decision is therefore `inconclusive`.

This distinction is normative: the LIN-0 work item produced a ready-to-run gate,
but the parent scheduler gate did not become go. LIN-1 must not be unblocked on
the strength of the public rehearsal.

Can the RH-01 direct source-lineage design survive the representative
workplace's leaf-program topology, project-reference/declaration behavior,

## Evidence ledger

### Documented facts

**`LIN0-FACT-01` — The governing gate requires representative input.** RH-01
allows production work only after a sanitized representative workplace slice
passes the feasibility gates. A public fixture cannot establish workplace
topology, convention prevalence, or scale.

**`LIN0-FACT-02` — Missing measurements are a stop, not a failed experiment.**
RH-01 states that unavailable scale measurements stop rollout. In this packet,
missing evidence maps to `inconclusive`; a measured budget miss maps to
`no-go`.

**`LIN0-FACT-03` — Program identity and symbol identity are separate.** The
RH-01 design requires exact leaf configs and a portable cross-program join; it
forbids comparing in-memory TypeScript symbols or symbol spelling across
programs.

### Reproduced observations

**`LIN0-OBS-06` — The retained anchor report is disclosure-safe under the

## Exact decision semantics

The required check list is fixed in code; input cannot remove a check or set the
decision.

1. A `public-anchor` result is always `inconclusive`, even if every rehearsal
   check passes or one rehearsal fails. Synthetic failure is retained as a
   limitation, not misreported as a workplace no-go.
2. A representative input not explicitly marked sanitized is
   `inconclusive`.
3. A sanitized representative input with any missing check is
   `inconclusive`.
4. A sanitized representative input with an observed wrong unique match,
   cross-program/overlap mismatch, forbidden bundle value, privacy leak, or
   measured budget overrun is `no-go`.
5. `go` is possible only when every fixed check passes on the sanitized
   representative input.

## Confidence and limitations

Confidence is **high** in the decision-state rules, canonical serialization,
path containment, privacy audit, and the harness behaviors covered by focused
tests. Confidence is **medium** that the manifest can express the expected
representative topology: the temporary program-reference/declaration and
overlap controls pass, but a real build host may add semantics that the input
must record as separate programs. Confidence in a workplace go is **none**
because no workplace evidence was supplied.

The harness is deliberately not a hermetic production staleness index, general
route analyzer, bundle graph analyzer, incremental TypeScript service, or form
inventory authority. Bundle cycle status and performance samples are explicit
reviewed inputs; the runner validates and retains them but does not invent
them. A dynamic lazy loader is counted, not interpreted. An exhaustive
workplace inventory remains a human-reviewed sampling boundary.
